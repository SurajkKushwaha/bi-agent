AI Business Intelligence Agent: how it works

Ask a business question in plain English or Hinglish. The agent finds the right data across four sources, writes and runs safe SQL, and explains the answer, showing the SQL it used.

Project files: one job each

loader.py

Reads the 4 sources (including the live Google Sheet link), fixes dates and saves 10 tables into warehouse.duckdb.

data_notes.md

The agent's briefing: tables, joins, business definitions (like revenue) and known data problems.

tools.py

Three @tool functions: list_tables, get_schema and run_sql with safety checks.

agent.py

ChatGroq LLM + system prompt + data notes + tools + memory, joined by create_agent.

app.py

The Streamlit chat: history sidebar, English/Hinglish switch, example questions, Show SQL. Builds the warehouse if it's missing.

.env · .streamlit/

Secrets (Groq key, sheet link) kept out of code, plus the ConsoleFlare theme and logo.

Safety in layers

No single check is trusted alone. Each layer catches what the one before might miss.

1
Scope rule in the promptOnly answers questions about the company data.
2
Look before writingMust check tables and schemas, never guess column names.
3
SQL guardSELECT/WITH only, one statement, dangerous words blocked.
4
Row limitAdds LIMIT 200 so huge results never reach the LLM.
5
Read-only databaseDuckDB itself refuses any write, even if a check had a bug.
6
Honest answersFacts kept separate from possible reasons; numbers only from query results; tables used are listed.
